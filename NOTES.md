# Notes

The `Note` model enforces that `note` is present, is a string, and is between 1 and 200 characters long; I wrote no validation code of my own for any of that. FastAPI answers the rest without code from me: it returns its standard 422 for a malformed JSON body, for a non-integer `limit` or `id`, and for a negative `limit`, which I declared with `ge=0` on the `Query` parameter rather than in the model. It also serves the interactive docs, and `GET /docs` returns 200.

Events are kept in a module-level dict, `EVENTS`, mapping integer ids to note strings. CHOOSE ONE: [A: Ids come from an `itertools.count(1)` counter taken under a `threading.Lock`, so two simultaneous POSTs cannot receive the same id; they start at 1 and increase with every POST.] [B: Each new event gets the highest existing id plus one (`max(EVENTS, default=0) + 1`), so ids start at 1 and increase with every POST. Plain `def` endpoints run in a threadpool, so two simultaneous POSTs could compute the same id and one event would overwrite the other; I did not guard against this.] `GET /events` sorts ids in descending order to return the most recent first, and uses a default limit of 10 when `limit` is absent. Everything lives in process memory, so a restart empties the store and the next id is 1 again.

I tested with curl against the running Uvicorn server: a listing on an empty store, three POSTs with ids 1 to 3, the newest-first listing, `?limit=2` and `?limit=0`, a GET for an existing id and a missing one, and `GET /docs`. Notes of 1 and 200 characters were accepted and 201 characters was rejected, and these bodies all returned 422: an empty note, `{}`, `{"note": 123}`, `null`, a list, text that is not JSON, and an empty body. A negative or non-integer `limit` and a non-integer id also returned 422.
